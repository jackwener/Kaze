---
name: 导出支付宝全部账单
description: 当用户要把支付宝的历史账单/消费记录全部导出成表格（或据此做消费分析）时使用。
start_url: https://consumeprod.alipay.com/record/standard.htm
sites:
  - alipay.com
  - consumeprod.alipay.com
kind: task
---

先把前提一条条核过，缺一条就停下来问用户，别硬跑：
1. 账单页（consumeprod.alipay.com/record/standard.htm 或 advanced.htm）的登录态必须在一个我能控制的标签里。用户从别的窗口附上来的标签，我能 read_tab 读文字却驱动不了——用 browser.tabs.new 开自己的标签去同一地址，若被跳到 auth.alipay.com，就让用户在这个标签里扫码登录一次，这是唯一需要他动手的地方，不要索要账号密码。
2. 页头是「你好，XXX」，确认是用户本人；有多个支付宝账号先问清导哪个。
3. 问清范围（默认全部；或最近 1 个月/1 年/某一年）和要 CSV 还是要分析结论。
4. 记下页脚「共 N 条」，它是后面校验完整性的唯一标准。

抓取流程：
1. 在该标签开网络录制，然后在账单页点一次「下一页」。从录到的请求里取那条账单接口的完整 URL（/record/standard.htm 或同名 .json，参数形如 pageNum / status / category / dateRange）——原样复用这串，只改页码，别自己拼参数。
2. 在页面里用这串 URL 发 fetch，pageNum 从 1 递增，每页 10 条，翻到覆盖「共 N 条」为止；按流水号去重（翻页越界会重复返回末页数据）。
3. 别在一次 evaluate 里跑完几百页（默认 10s 超时会被打断）：先把拉取函数装进 window，每次只跑 20~30 页，返回已拉条数当进度。
4. 若某个时间段拉不到（简版账单有保留期），改用「对账单」或按年分段再拉，不要凭空补数据。

导出与汇报：
1. 一个 CSV 就够：时间、名称、对方、金额、状态、流水号；带 \ufeff BOM，金额保持两位小数字符串（支出为负、退款和收入为正）。
2. 退款是独立一行，统计支出时剔除，否则会重复计；报总数要和「共 N 条」对上，对不上就说明哪段缺了。
3. 汇报口径：总条数、时间跨度、支出合计、退款合计、Top 几个商户；不要动用户原来那个账单标签。
